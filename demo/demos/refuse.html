demonstration 2

When it does not understand, nothing happens.

The strongest thing a runtime can do is nothing at all. This is the run where it met an element it could not describe, refused it, and stopped — and the record of that refusal is the only thing it left behind.

After the refusal at #3 there is no outcome receipt, and there is not supposed to be one. An outcome receipt is a statement that something happened. Its absence is the statement that nothing did. Both halves matter: a runtime that only records what it did can be silent about what it tried, and silence is exactly what an audit is looking for.

The page it was looking at — four elements, one of which is deliberately undescribable. The runtime was pointed at it and told to file something.

what this does not show

It does not show that refusing is always right. A runtime that refuses too much is useless, and this one has a real failure rate on pages it has never seen. What it shows is which way it fails when it does fail: the refusal is written down, signed, and visible — not a step that quietly did the wrong thing and reported success.
