why this page exists

Nothing in the middle knows what a browser is.

Everything else on this site drives a page. This drives a directory, and it is the same runtime: the same shape of decision, the same gate, the same rules document, the same signed receipts. Only two things differ — what counts as state (the entries of a directory) and what counts as an action (a shell command).

mint dir-learn --dir DIR --goal GOAL --skill SKILL.json
mint dir-run   --skill SKILL.json --dir DIR

The rule is in the names: invoice-2026-03-0147.pdf belongs in 2026-03. Both halves start from a fresh copy of the same fifty files, because a task that moves files cannot be run twice in the same place — comparing one side on work the other side has already done would be nonsense.

what is being measured

Decisions, not milliseconds.

The clock is interesting; the bill is the point. The ordinary agent asks a model about all fifty files, and it will ask again on every run, tomorrow and next week. mint asked fifty-one questions once — fifty for the files and one for the check that the work was done — and asks none now.

Verified on this machine: learned in 51 questions and 39 s; replayed in a different directory in 0.14 s with 0 model calls, all fifty invoices in their month folders — checked by a script, not by eye: nothing left loose, nothing in the wrong folder.

the gate, on a filesystem

A move is a write, and a write needs an approval.

Run the same skill under the shipped rules and it stops at the first move and names the exact action that needs approving — hold: this step commits something; it needs an approval for 5171e2cdcb8e — with nothing run. That is the gate doing to a directory what it does to a page, which is the claim this page is here to support.

what this does not show
WHAT THIS DOES NOT SHOW

It does not compare against a script. For a pile of files with a rule in the names, a person writes eight lines of shell in a minute, and those eight lines cost nothing at all. What mint is for is the task where you cannot write the script because you do not know the rule — the pile where deciding which file goes where needs judgement, and the judgement is the thing you want written down, approved once, and repeated without a model in the loop.

The left-hand half is the same runtime with a model deciding each step, so the two halves differ only in how a step is decided. Neither half is allowed to act without a decision being written first.
