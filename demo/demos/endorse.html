Four ways to lie about who agreed.

A receipt proves we did the work. It cannot prove anybody wanted it — a runtime signing its own rules is an author approving their own book. That takes a second key, held by somebody else. These are the four ways a second signature can be faked, and each is rejected for its own reason.

What a counter-signature is worth

Exactly what the key behind it is worth — no more, and no amount of code changes that. Two different key strings on the same machine prove the mechanism and nothing about trust, which is why the note above says so in the artifact itself rather than only in a pitch.

The four forgeries

signed by the runtime's own key

A perfectly valid signature — from the same party that wrote the rules. If a verifier accepts this, it will report a counter-signature where there is only one party agreeing with itself, which is worse than having none at all: the reader stops looking for the missing half.

what this does not show
It does not show that a real counterparty exists. Nobody outside this machine has signed anything here, and no code can supply that. The endorser's key is generated on this machine by a command that says out loud what it is for. A genuine endorsement needs a person or an organisation on the other side who was asked and agreed, and that is the one part of this that has to be bought rather than built.
