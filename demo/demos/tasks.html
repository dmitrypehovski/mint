demonstration 7

Eighteen tasks against six real repositories.

These are the actual runs, with their actual numbers: how many decisions, whether the model was needed, how long, and whether the step landed on the thing it was supposed to land on.

← all demonstrations

What each column means

decisions is how many times the runtime had to decide what to act on. The first task on a repository usually needs two; the shape is new. The next ones need one, because the same shape was already compiled.

model calls is how many of those decisions had to be asked about. Zero means the compiled skill recognised the page on its own.

landed is what the runtime was expected to reach — a commit page, an issue list, a pull request list — and it either did or did not.

Nothing here is averaged into a score. A number that hides which task failed is not a measurement, it is a claim about measurements.

the file: /evaluation.json — every run, with its per-run receipts

what this does not show

It does not show that this generalises past the family of pages it was tested on. Clean, well-marked pages with stable structures are the easy case, and these are all such pages. Four separate failures on other pages are named elsewhere on the site rather than folded into a percentage.
