mint — an agent runtime that does not pay twice for the same decision.

  mint probe --url URL
      look at a page and report what its perception costs

  mint learn --goal G --start URL --skill FILE [--max-steps N] [--category C]
      solve a task with a model in the loop and write the experience down as a program

  mint race --skill FILE --start URL
      the same task twice: the old path against the compiled one

  mint eval --jobs FILE --out FILE.json [--labels FILE] [--category C]
      run the compiled skills and give a verdict for every task

  mint chain --jobs FILE [--push URL] [--max-steps N]
      many tasks in a row, streamed to the showcase page

  mint discover --urls FILE --skill FILE --out FILE.json [--discovery URL --seed URL]
      cover a class of targets with one compiled skill and give a verdict for each

  mint traces --eval FILE --out FILE.jsonl
      write every verified run as documents a reactive store could hold

  mint arli-payload --skill FILE --out FILE.json [--price N --category C --subcategory S]
      shape a compiled skill as a marketplace listing (entries of terms and answers)

  mint endorse --policy FILE.json --scope TEXT [--note TEXT] [--days N] [--out FILE.json]
    put a counterparty's signature on a policy: these rules, for this runtime, in this scope.
    Runs under a separate key — the runtime must never mint its own endorsement

  mint receipts --in FILE.json [--policy FILE.json] [--endorsement FILE.json] [--tamper DIR]
    check a signed log: every signature, every link, and — with --policy — that the published rules
    reproduce every recorded verdict. With --endorsement, also check that somebody other than the
    runtime signed those rules, and report the endorsement if it does not hold. With --tamper, also
    check copies that lie

  mint live --skill FILE.json --start URL [--push URL] [--receipts FILE.json]
    run one already-learned task on a live page, in front of whoever is watching, and sign what it
    does. No model is called unless a step cannot be recognised at all. Drives a real browser, so it
    is meant to run one at a time

  mint gate-demo [--url URL] [--out FILE.json]
      put four kinds of element to the write gate and show what it decided, and why

variables: MINT_MODEL, MINT_MODEL_URL, MINT_MODEL_API, MINT_API_KEY

Environment for the run's identity, read the same way the keys are:
  MINT_PRINCIPAL         who this run answers to (an organisation or person), recorded in each receipt
  MINT_PRINCIPAL_CLASS   HUMAN | SERVICE | POLICY | SANDBOX_SIM — anything else is refused
  MINT_APPROVER          who approved held actions, recorded only when an approval was actually used

Verification returns a non-zero exit code when a log does not hold, so a script can act on it.

  approve                       issue an approval for one action, signed with the approver's own key
    --action <identity>         the action being authorised, as the gate prints it
    --for <agent hex>           the runtime it is issued for (default: this machine's receipt key)
    --days <n>                  how long it stays valid (default 1)
    --issued-ms/--expires-ms    place it in time, for demonstrations and tests
    --note <text>               why it was given, in the issuer's words
    --out <file>                where to write it (default approval.json)

  approve-check                 put one approval through the checks a run applies
    --approval <file> --action <identity> [--approvers <file>] [--agent <hex>] [--at <ms>]
                                exit status is 0 when it holds and non-zero when it does not

  guard                         judge ONE action, write the receipt, and say so in the exit status
    --command <string>          the command you are about to run, read by the shell adapter
    --action <file|->           one observation in the recorded shape (stdin with -)
    --policy <file>             the rules to judge by (default: the shipped document)
    --approval <file>           an approval to present, checked against this exact action
    --approvers <file>          the approvers to check it against (default: MINT_APPROVERS)
    --receipts <dir>            append the decision to <dir>/guard.json, continuing the chain
                                exit status: 0 allowed, 2 held, 1 refused

The loop an agent uses: guard → held (2), with the action named → a person approves that name with
`mint approve` → guard again with --approval → allowed (0), and the receipt carries the approver's name.
